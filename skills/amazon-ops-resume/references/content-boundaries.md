# Content boundaries

## Truth boundary

- A summary may synthesize supported facts but may not introduce a new level of seniority.
- A skill must be supported by at least one experience, project, credential, or artifact.
- A result must retain its original scope, period, unit, denominator, and responsibility boundary.
- Rounded or generalized confidential values require explicit user approval.
- Years, title, salary, or a target JD cannot by themselves prove management, P&L ownership, multi-market scope, or strategic responsibility.
- A stretch positioning may surface existing next-level evidence, but must list the proof still missing before the claim is safe.

## Reference-design boundary

When a user supplies a reference resume:

1. extract abstract design attributes such as density, section hierarchy, alignment, and typography;
2. rebuild with original CSS and component structure;
3. do not reproduce distinctive labels, ornamental marks, exact spacing system, code, or proprietary text;
4. tell the user when only general principles were retained.

## Photo policy

Default templates contain no portrait area. Add a photo only on explicit request and only after rebalancing layout; never leave a blank photo placeholder.

## Privacy boundary

Public fixtures must be synthetic from scratch. Private source data stays in user-requested outputs and must not be copied into repository examples.
